BUILD A COMPLETE PERSONAL AI OPERATING SYSTEM
1. PROJECT OVERVIEW
Build a production-quality full-stack web application called:
**Personal AI OS**
The application should work as an **AGI-inspired personal AI operating system** that can understand high-level user goals, create plans, break goals into tasks, select specialized agents, use tools, retrieve information from memory/files, execute tasks, verify results, ask for human approval when necessary, and learn from previous interactions.
This must NOT be a simple chatbot.
The core concept is:
**User Goal → Understanding → Planning → Task Decomposition → Agent Selection → Tool Use → Execution → Verification → Memory → Replanning**
The system should have a polished, modern AI operating-system-style interface.
2. IMPORTANT PRODUCT POSITIONING

6. AGENT ARCHITECTURE
Create the following core agents.
6.1 Planner Agent
Responsibilities:

- Understand user's high-level goal
- Determine intent
- Analyze complexity
- Break goal into tasks
- Determine task dependencies
- Select required agents/tools
- Create execution plan

Example:
User:
"Help me prepare for an AI Engineer interview."
Planner creates:
Goal:
Prepare for AI Engineer interview

Tasks:

1. Analyze job description
2. Identify required skills
3. Compare with user profile
4. Identify skill gaps
5. Create study plan
6. Generate interview questions
7. Conduct mock interview
8. Evaluate performance
9. Recommend improvements

6.2 Research Agent
Responsibilities:

- Search available web/search tools
- Gather information
- Summarize findings
- Cite sources where applicable
- Detect duplicate information
- Evaluate source quality

6.3 Task Agent
Responsibilities:

- Create tasks
- Update task status
- Prioritize tasks
- Mark tasks completed
- Detect failed tasks
- Manage dependencies

6.4 File Agent
Responsibilities:

- Process uploaded documents
- Extract text
- Search documents
- Answer questions using documents
- Provide relevant document references

Supported initial file types:

- PDF
- TXT
- DOCX
- CSV

6.5 Memory Agent
Responsibilities:

- Store useful long-term user information
- Retrieve relevant memories
- Decide whether information is worth remembering
- Avoid storing unnecessary information
- Update existing memories

Memory categories:
preferences
goals
projects
work_style
important_facts
past_decisions
learned_information

6.6 Critic / Verification Agent
Responsibilities:

- Review agent output
- Detect mistakes
- Check completeness
- Verify task completion
- Decide whether to accept or reject output

Output:
{
  "approved": true,
  "score": 0.92,
  "issues": [],
  "recommendation": "complete"
}

If rejected:
Agent Output
      ↓
Critic
      ↓
REJECT
      ↓
Planner
      ↓
Retry / Replan

6.7 Communication Agent
Initially support:

- Email drafting
- Message drafting
- Communication summarization

Do NOT automatically send emails without user approval.

The agent workflow must pause while waiting for approval.
After approval, continue execution.
10. MEMORY SYSTEM
Implement two memory levels.
Short-Term Memory
Conversation/session context.
Long-Term Memory
Persist useful information in MongoDB.
Example document:
{
  "user_id": "...",
  "type": "preference",
  "content": "User prefers concise professional emails",
  "importance": 0.85,
  "created_at": "...",
  "updated_at": "..."
}

Use embeddings for semantic retrieval.
Do NOT blindly save every conversation message as memory.
Create a memory extraction step that decides what is useful.
